# Asset Pipeline

CLI-first. Every asset is **generated by a script**, saved as a `.blend` source, exported to glTF and imported into Godot, all headless. No editor has to be open. A full rebuild from an empty checkout takes about 15 s on the M3 Pro.

```
tools/textures/*.py ──► game/textures/ink/*.png
tools/blender/build_*.py ──► assets_src/**/*.blend ──► tools/blender/export_assets.py ──► game/assets/**/*.glb
                                                     (tools/asset_manifest.json)
game/data/ink_materials.json ──► game/tools/build_materials.gd ──► game/materials/M_*.tres
godot --import  +  game/tools/import/ink_post_import.gd  (material swap by name, loop flags)
validators: tools/validate/validate_blender.py  +  game/tools/validate_assets.gd ──► build/reports/*.json
```

## Commands

| | |
|---|---|
| `make all` | textures → sources → glTF → Godot import → both validators |
| `make kage` / `daggers` / `shrine` | rebuild one source |
| `make export` | all `.glb` from the saved sources |
| `make godot-import` | import, build materials, pin import settings, re-import |
| `make validate` | both validators (non-zero exit on error) |
| `make renders` | Blender turnaround sheets + in-engine Godot shots into `docs/renders/` |
| `make clean-generated` | delete everything regenerable |

Override tool paths with `BLENDER=… GODOT=… make all`. Tested with **Blender 5.3** and **Godot 4.7.2** on macOS (Apple Silicon).

`renders-godot` is the only step that opens a window, because headless Godot has no renderer. It runs `game/scenes/showcase/showcase.tscn -- --shots=…` and exits by itself.

## Conventions

| Topic | Rule |
|---|---|
| Units / axes | metres; Blender Z-up with characters facing −Y; glTF/Godot Y-up with characters facing +Z (`MODEL_FRONT`) |
| Names | assets `snake_case`; objects `Asset_Part`; materials `M_<Asset>_<Part>` (shared: `M_Ink_*`); bones = Godot humanoid profile names; sockets `*Weapon` / `*SheathBack`; VFX empties `Socket_*` |
| Weapons | origin = grip centre. **Blender:** blade +Z, edge −Y. **Godot:** blade +Y, edge +Z. That equals the `*HandWeapon` bone frame, because glTF converts mesh space but keeps bone axes (verified by the Godot validator) |
| Materials | Blender materials are previews; the Godot ink material with the same name replaces them on import |
| Vertex colour | `Color` attribute: R = cavity (0 crevice … 1 exposed), G = normalised height. Baked by `sumi.bake_cavity_to_color()` |
| Normals | every lofted mesh is auto-oriented outward (`sumi.orient_outward`). Back-face culling and the inverted-hull outline depend on it |
| Skinning | ≤ 4 influences, normalised, no unweighted vertices; only deform bones exported (`CTRL_*` stay in the source) |
| Collision | Godot import suffixes on object names: `-col`, `-convcol`, `-colonly` |
| Status | `tools/asset_manifest.json` `status`: `final-v1`, `blockout` or `placeholder`. Blockout objects also carry the custom property `sumi_status` |
| Budgets | per asset in the manifest; both validators enforce triangles and materials, plus bones on characters |

## Adding an asset

1. Write `tools/blender/build_<asset>.py` using `tools/blender/lib/sumi.py`: it saves a `.blend` with an `Export_*` (or named) collection.
2. Add an entry to `tools/asset_manifest.json` (source, collection, output, kind, status, budget, expectations).
3. Add any new `M_*` materials to `game/data/ink_materials.json`.
4. Run `make all`. The importer warns about unmapped materials; the validators fail on budget, naming, UV, skinning or socket problems.

## What each validator checks

**Blender source** (`build/reports/validation_blender.json`): unapplied scale, missing UVs, empty or misnamed material slots, loose vertices, zero-area faces, cavity colours, triangle/material/bone budgets, `CTRL_` bones not deforming, sockets present, every mesh bound to the rig, ≤ 4 normalised influences with no unweighted vertices, required actions, rest height, blockout tagging, collision object count.

**Godot import** (`build/reports/validation_godot.json`): every asset imports; triangles and materials within budget; every surface uses an ink `ShaderMaterial` (proves the post-import mapping ran); one `Skeleton3D` covering the full `SkeletonProfileHumanoid`; socket bones present; **`LeftHandWeapon` frame orientation**; normalised skin weights; required animations present and stance clips looping; rest height; weapon length and origin; collision shapes generated; all JSON materials built.

## Known pipeline notes
- In background mode Blender's `vertex_group_limit_total` / `normalize_all` operators silently do nothing on some objects. Weight hygiene is done in Python (`finalize_weights`). The source validator caught this; the glTF exporter had been hiding it.
- Godot re-imports when `.import` params change. `tools/configure_godot_imports.py` owns the keys we pin, which keeps the import configuration in text and under review.
- Repository hygiene: `.gitattributes` routes `.blend/.glb/.png` through Git LFS once the repo is initialised; `build/` and `game/.godot/` are ignored.
